Актуализируй всю документацию по проекту, какая есть (`README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `SYNC_SETUP.md`, `.agent/workflows/*.md` и др.).

## Правила версионирования

1. Проверь текущую версию проекта в `package.json` (и `package-lock.json`), а также последние git-теги (`git tag --sort=-v:refname`).
2. Не используй секцию `## [Unreleased]` в `CHANGELOG.md` — всегда выставляй конкретную новую версию по SemVer в формате `## [X.Y.Z] - YYYY-MM-DD` (с текущей датой):
   - Если текущая версия уже выпущена (есть соответствующий git-тег `vX.Y.Z` или запись `## [X.Y.Z]` в `CHANGELOG.md`), увеличь её:
     - `patch` (`X.Y.Z+1`) — для исправлений, мелких улучшений и UI-доработок;
     - `minor` (`X.Y+1.0`) — для заметных новых возможностей или архитектурных изменений;
     - `major` (`X+1.0.0`) — для несовместимых изменений (breaking changes).
   - Если пользователь явно указал желаемую версию — используй именно её.
3. Синхронно обнови эту же новую версию везде в проекте (`package.json`, `package-lock.json`, `CHANGELOG.md` и другие файлы, где указана версия).
4. Проверь, что заголовок `## [X.Y.Z] - YYYY-MM-DD` в `CHANGELOG.md` совпадает с `version` в `package.json` и корректно извлекается скриптами релиза и CI (`.github/workflows/publish.yml`, `release_local.js`).
